# StarToDo 自适应执行台与专注伴侣设计规格

状态：待用户评审
日期：2026-08-25

## 1. 目标与范围

StarToDo 的产品主轴是“今天的执行台 + 随时可进入的专注伴侣”。

第一阶段重构前端应用壳层、任务和专注场景、上下文抽屉、悬浮窗状态机以及主窗口自适应行为，同时保留现有任务、提醒、通知激活、项目、周计划、回收站和 Pomodoro 能力。

高效能工作台的快捷命令、批量键盘流和高密度布局列入第三阶段。第一阶段不引入积分、等级、排行榜或新的任务业务模型。

## 2. 已确认的产品决策

- 任务场景是默认主场，第一眼回答“今天现在该做什么”。
- 专注场景是任务场景的注意力模式，计时器成为视觉中心。
- 主窗口默认最大化到 Windows 可用工作区，保留任务栏；普通窗口仍可自由缩放。
- 首次使用询问是否在开始专注时进入真正全屏，默认不强制，设置中可修改。
- 沉浸退出支持页面按钮和 Esc，并恢复进入前的窗口状态。
- 原 compact 主窗口模式废弃，紧凑体验由呼吸式悬浮窗承担。
- 悬浮窗专注中默认胶囊，最近交互时展开，4-6 秒无操作后收拢；支持始终展开偏好。
- 动效采用安静的星光反馈、缓慢呼吸环和轻量抽屉过渡，不做强游戏化。

## 3. 信息架构

应用壳层包含任务场景、专注场景和沉浸显示层：

```text
AppShell
+-- TaskScene: 今日执行画布、轻量导航、快速捕获
+-- FocusScene: 居中计时画布、阶段控制、任务上下文
+-- ImmersiveLayer: 隐藏非必要导航、居中放大计时、边缘上下文抽屉
```

任务场景常驻应用状态、轻量导航、快速捕获、今日任务列表和当前专注条。项目、周计划、回收站、提醒详情和诊断通过抽屉进入。

默认执行顺序为“现在处理 -> 今天剩余 -> 已完成”。逾期、即将到来、全部和状态筛选进入筛选入口。

任务卡片的主动作是完成/恢复、打开详情和开始专注；延期、稍后、删除和编辑为次级操作。

专注场景常驻阶段、剩余时间、当前任务、主控制和返回入口；绑定任务、周期统计、今日统计、下一阶段和设置属于上下文抽屉。

任务卡片进入专注只预选任务，不自动开始计时。返回任务场景时恢复筛选、搜索、滚动位置和焦点。

沉浸式不是独立路由。应用重启时默认回到普通任务场景。

悬浮窗状态机：

```text
expanded -> capsule -> interaction-expanded -> capsule
```

空闲时展开，专注时胶囊，鼠标移入、键盘聚焦或点击后交互展开。自动收拢不得抢夺焦点或截断输入。

## 4. 全屏自适应布局

根节点固定在 100dvh 内。html、body 和应用壳层不得产生页面级滚动；任务列表、抽屉和周计划拥有明确的局部滚动区域。

编辑表单使用覆盖式面板，Toast 不参与主布局高度。周计划宽屏显示七日列；窄屏改为日期条和当前日期任务，不依赖整页横向滚动。

普通场景默认最大化到 Windows 工作区并保留任务栏。应用记住最大化前的普通窗口 bounds、最大化状态和进入沉浸前的窗口状态。

进入沉浸使用 Tauri 系统全屏，退出时精确恢复。系统调用失败时回退为窗口内沉浸画布并显示非阻塞提示。

主窗口建议最小尺寸约 520 x 420；浏览器预览继续兼容 320px 且不得水平溢出。

宽度规则：

- >= 1180px：文字侧栏、居中主画布、可选上下文栏。
- 760-1179px：图标窄栏，项目、周计划和上下文进入抽屉。
- 520-759px：导航收进顶部菜单或侧滑层，任务单列。
- < 520px：应急窄屏布局，非必要内容使用覆盖式面板。

高度规则：

- >= 760px：舒适密度，显示完整标题、捕获提示和辅助元数据。
- 560-759px：标准密度，压缩标题和间距。
- 420-559px：顶部栏约 44px，隐藏帮助文字，列表占据剩余高度。
- < 420px：仅浏览器预览降级；正常 Tauri 窗口不允许进入该高度。

任务画布由标题/筛选、快速捕获、任务滚动区和当前专注条组成。专注画布由轻量导航、居中 FocusStage 和上下文抽屉入口组成。

使用 CSS Grid、minmax(0, 1fr)、min-height: 0 和容器查询。

## 5. 视觉语言与互动

语义颜色固定为：

- 橙色：当前专注、主要行动、计时进度。
- 蓝色：导航、选中状态、信息提示。
- 绿色：完成和成功。
- 琥珀色：提醒异常和错过事项。
- 红色：危险操作和不可恢复错误。

橙色只用于“现在正在做的事”。减少矩形卡片嵌套，以连续画布、分隔线和少量抬升表面表达层级。星形只用于品牌、进度节点和完成反馈。

完成任务时先更新数据，再播放 350-450ms 的星点光晕、任务淡化和列表补位动画。动画不阻塞命令，焦点移动到下一个可执行任务。

第二阶段可增加按完成时间派生的“今日星图”，不增加积分或数据库表。

专注进度环每 6-8 秒轻微呼吸；开始、暂停和继续只产生一次短反馈；阶段切换显示一次柔和环形扩散并触发系统通知。

悬浮窗展开约 180ms、收拢约 240ms，鼠标离开保留约 700ms 缓冲。键盘焦点在面板内时不收拢。

用户手动调整窗口尺寸后，自动模式只改变内部布局，不强制覆盖用户尺寸；外层尺寸调用需要防抖。

第一阶段支持任务行悬停/聚焦快捷动作、解析结果标签、专注条定位、键盘任务导航、Space 完成和 Ctrl/Cmd + Enter 提交捕获。

周计划第一阶段使用明确日期选择，拖拽排期列入第二阶段。所有状态同时使用文字、图标和语义属性表达，并支持 prefers-reduced-motion。


+page.svelte 保留 Tauri 生命周期、业务快照和事件协调，但不再直接承担全部布局。

现有任务操作序列、提醒告警租约、Pomodoro 结算和悬浮窗 pending intent 机制继续保留。视觉组件只接收纯数据和回调，不复制 SQLite 或 Tauri 业务逻辑。

## 7. 状态与数据流

```text
Rust / SQLite
    |
    v invoke + Tauri events
+page.svelte 协调层
    |
    v 数据 + 回调
TaskScene / FocusScene / FloatingWindow
    |
    v 用户操作
统一命令函数 -> Rust / SQLite
```

业务状态包括 tasks、projects、reminders 和 Pomodoro snapshot。

UI 状态包括 activeScene、openDrawer、immersive、floatingDisplayMode、lastInteractionAt 和 alwaysExpanded，不写入任务或 Pomodoro 数据表。

## 8. Tauri 窗口与偏好迁移

WindowPreferences 从 full / compact 迁移为 adaptive，记录布局类型、最大化状态、普通窗口 bounds、置顶状态、自动沉浸三态偏好和上次沉浸状态。

旧 compact 设置读取时映射为 adaptive；托盘菜单移除 Compact mode。窗口几何由 Rust 持久化，场景、抽屉、筛选、自动沉浸和悬浮窗始终展开偏好由前端偏好层持久化。

建议使用明确语义的窗口命令：

- enter_immersive_mode
- exit_immersive_mode
- get_window_state
- set_floating_display_mode

旧 set_window_mode 可暂留用于迁移兼容，但不再作为新 UI 的通用模式接口。

## 9. 错误处理

业务命令失败时保留当前场景和用户输入，在 Toast 或场景内警告中显示并支持重试。

全屏、bounds 恢复或悬浮窗缩放失败时只回退显示状态，不影响任务和计时数据库。

无效偏好使用安全默认值并记录到诊断层。动画不阻塞命令。

现有任务操作序列、提醒租约、Pomodoro 结算、通知激活重试和悬浮窗跳转恢复机制必须保留。

## 10. 验证策略

前端纯逻辑测试覆盖响应式密度选择、悬浮窗状态机超时、旧窗口偏好迁移、自动沉浸三态和手动调整悬浮窗后的尺寸保护。

Playwright 覆盖：

```text
320 x 720
520 x 420
760 x 560
1180 x 760
1440 x 900
```

验证页面级 scrollWidth <= innerWidth、scrollHeight <= innerHeight，并确认局部滚动只存在于任务区或抽屉。

还要验证场景切换、焦点恢复、Esc 退出沉浸、减少动态、键盘完成任务、抽屉开关和浏览器预览无控制台错误。

Rust 测试覆盖窗口偏好迁移与校验、沉浸前后状态恢复、浮动窗口尺寸校验、无效状态回退和托盘不再触发 compact 模式。

Windows smoke test 记录最大化工作区、自由缩放、真正全屏恢复、托盘隐藏、悬浮窗呼吸状态、通知激活、Pomodoro 阶段通知、悬浮窗跳转、安装后启动、协议激活和卸载。

## 11. 分期、非目标与验收

第一阶段：自适应应用壳层、任务/专注场景、抽屉、沉浸偏好、悬浮窗状态机和窗口偏好迁移。

第二阶段：星光完成反馈、专注星环、今日星图、拖拽排期和更丰富但可关闭的微交互。

第三阶段：快捷命令、键盘优先工作流、批量处理和高密度工作台。

第一阶段不做多窗口业务拆分、不新增积分体系、不做排行榜或等级、不改变 SQLite 任务语义，也不禁止局部滚动。

验收标准：

- 默认打开后用户首先看到今天的可执行任务。
- 场景切换不会丢失业务状态、筛选、滚动位置或焦点。
- 主窗口默认利用可用工作区，普通窗口可自由缩放，页面外层无滚动。
- 专注可以进入和退出真正沉浸，并恢复进入前的窗口状态。
- 悬浮窗在空闲、专注和交互状态之间按规则呼吸，不抢焦点。
- 完成反馈清晰、短暂、可关闭动态，不引入游戏化负担。
- 现有任务、提醒、通知激活、项目、周计划、回收站和 Pomodoro 继续可用。
- 前端检查、单元测试、Rust 测试、构建和 Windows smoke test 均有记录。

## 12. 实施前检查清单

- 先迁移窗口偏好模型，再删除 compact 用户入口。
- 先建立场景和抽屉边界，再移动任务业务处理。
- 先为局部滚动建立高度约束，再调整视觉间距。
- 每个窗口 API 失败路径都有前端回退。
- 所有动效都有 reduced-motion 分支。
- 视觉演示和生成目录不进入应用构建产物。
